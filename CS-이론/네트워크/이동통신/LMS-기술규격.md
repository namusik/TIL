# LMS 기술 규격

> 최종 업데이트: 2026-06-13 | 한국 통신사 장문 메시지(LMS) 등급 기준

## 개념

**LMS(Long Message Service, 장문 메시지 서비스)** 는 **첨부 없는 긴 텍스트를 한 건으로 보내는 메시지 등급**이다. SMS의 짧은 길이(한글 약 45자)를 넘는 장문 텍스트를 위한 것으로, **한국 통신사가 만든 특유의 등급**이다.

> 비유: LMS는 **"사진 빠진 택배"** 다. [MMS](MMS-기술규격.md)라는 택배 시스템(서버 경유·데이터망)을 그대로 쓰되, 짐칸에 사진·영상 없이 **긴 글만** 싣는다.

핵심은 LMS가 [SMS](SMS-기술규격.md)를 늘린 게 **아니라**, 사실상 **텍스트만 담은 MMS**라는 점이다. SMS의 140바이트 회선 방식으로는 장문이 불가능하니, MMS 인프라(MMSC 서버 + 데이터망)를 재활용해 2,000바이트를 실현했다.

## 배경/역사 — 왜 한국에만 있나

LMS는 국제 표준(3GPP)이 정한 등급이 아니다. **한국 통신사가 자국 수요에 맞춰 만든 분류**라, 영어권엔 "LMS"라는 등급 자체가 없다.

| 구분 | 장문 텍스트 처리 방식 |
|------|---------------------|
| **해외 (대다수)** | **Concatenated SMS** — 긴 글을 여러 SMS로 쪼개 보내고 단말이 합침 |
| **한국** | **LMS** — 분할 없이 **한 건의 장문(2,000바이트)** 으로 처리하는 별도 등급 |

### 한글 2바이트가 만든 장문 수요

한국이 LMS를 일찍 상품화한 근본 이유는 **한글이 2바이트**라는 데 있다.

- 영어권: SMS 1건에 **160자** → 웬만한 문장이 한 통에 들어감. 장문 수요가 상대적으로 적음
- 한국: 한글 **70자(분할 시 67자)** 면 금방 초과 → **장문 수요가 훨씬 큼**

그래서 한국 통신사는 "쪼개 보내기(Concatenated SMS)"로는 부족하다고 보고, MMS 인프라를 텍스트에 끌어와 **LMS라는 장문 등급**을 따로 만들었다. [한글 2바이트 특성](../../한글-인코딩.md)이 인코딩을 넘어 **메시지 서비스 등급 구조까지 가른** 사례다.

## 전송 방식 — MMS 인프라 재활용

LMS는 SMS가 아니라 **MMS와 같은 방식**으로 전송된다. 즉 회선 제어 채널이 아니라 **패킷 데이터망 + MMSC 서버 경유**다.

```
① 발신 단말 ─(데이터망)→ [MMSC]에 장문 텍스트 업로드
② MMSC ─(SMS 도착 알림)→ 수신 단말
③ 수신 단말 ─(데이터망)→ [MMSC]에서 본문 다운로드
```

본문이 SMS 채널(140바이트 벽)이 아니라 **데이터망으로 서버를 거치므로** 2,000바이트가 가능하다. 자세한 MMSC 경유 메커니즘은 [MMS-기술규격](MMS-기술규격.md)에서 다룬다.

## 용량과 등급 전환

| 구분 | 용량 (한국 기준) | 내용 |
|------|----------------|------|
| SMS | 한글 약 40~45자 (80~90바이트) | 단문 텍스트 |
| **LMS** | 한글 약 **1,000자 (2,000바이트)** | **장문 텍스트** |
| MMS | 2,000바이트 + 이미지·영상 첨부 | 멀티미디어 |

- LMS 용량도 SMS의 90바이트처럼 **사업자 운영 기준**이며, 보통 2,000바이트(한글 1,000자)로 통용된다
- 발송 시 **SMS 한도(90바이트)를 넘으면 자동으로 LMS로 전환**되어 과금 단가가 오른다. 텍스트에 이미지가 붙으면 MMS로 전환된다

```
짧은 텍스트        →  SMS
길어짐(90B 초과)   →  LMS 자동 전환
이미지·영상 첨부    →  MMS
```

## 백엔드에서 LMS 발송

서버에서 LMS도 **문자 중계사 API**를 거친다. 보통 SMS와 같은 엔드포인트에 **본문 길이에 따라 자동으로 SMS↔LMS가 갈리거나**, 메시지 타입을 명시한다.

```
백엔드 서버 → 문자 중계사 API(HTTP) → MMSC → 데이터망 → 수신 단말
```

- 국내: NHN Cloud, 알리고, 네이버 클라우드 SENS 등 (SMS/LMS/MMS 통합 API)
- 인증번호처럼 짧은 건 SMS, 안내·공지처럼 긴 건 LMS로 나가므로 **길이에 따른 과금 차이**를 의식해 문구를 작성한다

## 정리

- **LMS** = 첨부 없는 장문 텍스트 등급. **한국 특유**(해외는 Concatenated SMS로 대체)
- 본질은 **텍스트만 담은 MMS** — MMS 인프라(MMSC·데이터망)를 재활용
- SMS의 140바이트 회선 방식이 아니라 **서버 경유**라 2,000바이트 가능
- 한국이 일찍 만든 이유: **한글 2바이트 → 큰 장문 수요**
- 90바이트 초과 시 SMS→LMS 자동 전환, 첨부 붙으면 MMS
