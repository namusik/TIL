# 이동통신 무선 채널

> 최종 업데이트: 2026-06-13 | GSM(2G) 논리 채널 중심 + 2G~5G 세대별 변화 포함

## 개념

이동통신 **무선 채널**은 폰과 기지국 사이의 한정된 무선 주파수를 **용도별로 쪼개 쓰는 통로**다. 크게 **실제 음성·데이터가 흐르는 트래픽 채널**과 **연결·위치 등록 같은 신호를 주고받는 제어 채널**로 나뉜다.

> 비유: 한 건물(주파수)을 용도별 방으로 나눈 것. **회의실(트래픽 채널)** 에서는 실제 대화가 오가고, **인터폰·관리실(제어 채널)** 에서는 "몇 호실 손님 오셨어요" 같은 안내 신호가 오간다. 둘은 같은 건물이지만 쓰임이 다르다.

이 채널 구분을 이해하면 **SMS가 왜 140바이트로 작은지, 통화 중에도 왜 문자가 오는지**가 자연스럽게 풀린다. SMS는 트래픽 채널이 아니라 제어 채널을 타기 때문이다.

> 이 문서의 본문(트래픽/제어 채널, SDCCH 등)은 **GSM(2G) 구조**를 기준으로 한다. **2G는 한국에서 이미 종료된 레거시**(LG U+ 2021년 5월 마지막)이지만, SMS의 채널 동작을 가장 명확히 보여주는 **개념 원형**이라 학습 기준으로 삼는다. 지금 한국 SMS는 LTE/5G의 NAS/IMS로 전송된다. 세대별 변화는 맨 아래 [세대별 채널 구조 변화](#세대별-채널-구조-변화)에서 다룬다.
>
> (엄밀히 한국 2G는 GSM이 아니라 CDMA 계열이었다. 이 문서는 글로벌 표준 GSM으로 채널 원리를 설명한 것이다.)

## 물리 채널 vs 논리 채널

채널은 두 층위로 나눠 본다.

| 구분 | 정의 | 비유 |
|------|------|------|
| **물리 채널** (Physical Channel) | 실제 무선 자원 = **주파수 + 타임슬롯**(TDMA) | 건물의 실제 '방' |
| **논리 채널** (Logical Channel) | 물리 채널 위에 얹는 **기능별 통로** | 그 방의 '용도(회의실/관리실)' |

GSM은 하나의 주파수를 시간으로 잘게 쪼개(TDMA) 여러 단말이 나눠 쓰고, 그 물리 자원 위에 **기능별 논리 채널**을 매핑한다. 우리가 "트래픽 채널", "제어 채널"이라 부르는 건 전부 **논리 채널의 하위 종류**다 — 물리 채널과 나란한 게 아니다.

**물리 vs 논리는 '층위' 구분, 트래픽 vs 제어는 '논리 채널을 기능별로 나눈 종류'** 다. 분류 축이 다르다. 전체를 계층으로 보면 다음과 같다.

```
무선 채널
├─ 물리 채널 (주파수 + 타임슬롯)   ← 실제 자원 (하드웨어 층)
└─ 논리 채널 (물리 채널 위에 매핑)  ← 기능별 통로
   ├─ 트래픽 채널 (TCH)   ← 음성·데이터
   └─ 제어 채널           ← 신호
      ├─ 방송 (BCH)
      ├─ 공통 (CCCH)
      └─ 전용 (DCCH)  ← SMS(SDCCH/SACCH)
```

아래 두 섹션(트래픽 채널·제어 채널)은 모두 **논리 채널의 하위**임을 염두에 두고 보면 된다.

## 논리 채널 ① 트래픽 채널 (Traffic Channel, TCH)

실제 **음성·데이터가 흐르는 통로**다.

| 종류 | 설명 |
|------|------|
| TCH/F | Full rate — 풀 대역 음성 |
| TCH/H | Half rate — 절반 대역(용량 절약) |

통화를 시작하면 망이 단말에 트래픽 채널을 **할당**하고, 통화 내내 점유한다. 통화가 끝나면 반납한다.

## 논리 채널 ② 제어 채널 (Control Channel / Signaling Channel)

음성이 아니라 **망 운영에 필요한 신호**를 주고받는 통로다. 통화 중이 아니어도 폰과 망 사이에서 **항상** 신호가 오간다. 역할에 따라 다시 세 갈래로 나뉜다.

### 방송 채널 (BCH, Broadcast Channel)

기지국이 일방적으로 **뿌리는** 정보. 단말이 망에 처음 붙을 때 듣는다.

| 채널 | 역할 |
|------|------|
| BCCH | 기지국 식별·망 정보 방송 |
| FCCH | 주파수 보정 |
| SCH | 동기화 |

### 공통 제어 채널 (CCCH, Common Control Channel)

망 ↔ 다수 단말이 **공유**하는 제어 통로.

| 채널 | 역할 |
|------|------|
| **PCH** (Paging) | 망이 "당신한테 전화/문자 왔어요" 하고 단말 호출 |
| RACH | 단말이 망에 최초 접속 요청 |
| AGCH | 망이 접속을 허가하고 채널 할당 |

### 전용 제어 채널 (DCCH, Dedicated Control Channel)

특정 단말 하나에 **전용으로 붙는** 제어 통로. **SMS가 실제로 타는 채널**이 여기 있다.

| 채널 | 역할 |
|------|------|
| **SDCCH** | 통화 설정·위치 등록·**통화 중이 아닐 때의 SMS** 전송 |
| **SACCH** | 통화·통신 중 부가 신호·**통화 중 SMS** 전송 |
| FACCH | 핸드오버 같은 긴급 신호(트래픽 채널 빌려 씀) |

## SMS는 어느 채널로 가나

SMS는 **트래픽 채널(음성용)을 쓰지 않는다.** 대신 항상 열려 있는 **전용 제어 채널(DCCH)** 에 데이터를 얹어 보낸다.

| 상황 | SMS가 타는 채널 |
|------|----------------|
| 통화 중이 아닐 때 | **SDCCH** |
| 통화 중일 때 | **SACCH** (그래서 통화 중에도 문자 수신) |

```
[문자 도착 흐름]
망 → PCH(페이징): "단말아, 너한테 메시지 있다"
단말 → RACH: "접속 요청"
망 → AGCH: "SDCCH 줄게"
망 → SDCCH: SMS PDU 전달
```

## 채널 설계가 만드는 SMS의 특성

SMS의 모든 제약이 "제어 채널을 탄다"는 한 가지 설계에서 나온다.

| 제어 채널을 타기 때문에 | 결과 |
|------------------------|------|
| 제어 신호용이라 용량이 작음 | **140바이트 제약** (대용량 불가) → [SMS-기술규격](SMS-기술규격.md) |
| 통화용 트래픽 채널을 점유 안 함 | **통화 중에도 문자 수신** (SACCH 이용) |
| 통화처럼 종단 연결을 안 맺음 | **connectionless**, fire-and-forget |

즉 SMS는 "음성 통화를 관리하려고 깔아둔 신호 통로에 짧은 메시지를 끼워 넣은 서비스"다. 처음부터 대용량을 의도하지 않은 이유가 이 채널 구조에 있다.

## 세대별 채널 구조 변화

지금까지 본 트래픽/제어 채널은 **GSM(2G)** 구조다. 세대가 올라가며 무선 접속 방식(TDMA→OFDMA 등, [무선-다중접속.md](무선-다중접속.md))과 채널 구조가 크게 바뀌었다. 다만 **"음성·데이터용 통로와 제어·시그널링용 통로를 나눈다"는 큰 원칙은 세대가 바뀌어도 유지**된다.

| 세대 | 무선 접속 방식 | 망 구조 | 제어/시그널링 경로 | 한국 현황 |
|------|--------------|---------|------------------|----------|
| **2G (GSM)** | TDMA | 회선교환(CS) | **SDCCH/SACCH** (이 문서 본문) | **종료**(2021) |
| **3G (UMTS)** | WCDMA | CS + 패킷(PS) | 전용 채널(DCH)·RRC 시그널링 (명칭·구조 상이) | **2026 만료 예정** |
| **4G (LTE)** | OFDMA | **All-IP** (CS 없음) | **NAS 시그널링** / **IMS(SIP)** | 현역 |
| **5G (NR)** | OFDMA | **All-IP** | **NAS 시그널링(SMSF)** / **IMS** | 현역 |

> 한국은 2G가 2021년 종료(KT 2012 / SKT 2020.6 / LG U+ 2021.5), 3G도 정부 발표로 2026년 이용기간 만료 예정이다. 즉 이 문서 본문의 GSM 채널은 한국 현역망이 아니며, 실제 SMS는 아래 LTE/5G 방식으로 전송된다. (전 세계로 보면 2G는 IoT용 등으로 일부 국가에 잔존.)

### LTE·5G에는 회선 제어 채널이 없다

핵심 변화는 **LTE부터 회선교환(CS) 도메인이 사라진다**는 점이다. 음성조차 IP로 흐르므로(VoLTE/VoNR), GSM식 회선 제어 채널(SDCCH 등)에 SMS를 얹을 수가 없다. 그래서 SMS의 **운반 경로가 IP 기반 시그널링으로 갈아끼워진다.**

| 세대 | SMS 운반 방식 | 처리 주체 |
|------|-------------|----------|
| LTE | **SMS over SGs** — NAS 시그널링 ⇄ 레거시 CS망 연동 | MME ⇄ (SGs) ⇄ MSC |
| LTE | **SMS over IMS** — SIP 메시지로 전송 | IMS → IP-SM-GW → SMSC |
| 5G | **SMS over NAS** — 5G NAS 시그널링 | AMF ⇄ **SMSF** |
| 5G | **SMS over IMS** — SIP 메시지 | IMS → SMSC |

- **NAS**(Non-Access Stratum): 단말 ↔ 코어망(MME/AMF) 사이의 제어 시그널링 계층. GSM 무선 제어 채널의 역할을 코어망 시그널링이 대신함
- **SMSF**(SMS Function): 5G에서 SMS를 전담하는 네트워크 함수 (신설)

### 변한 것과 안 변한 것

| | GSM (2G/3G) | LTE/5G |
|---|---|---|
| 운반 경로 | 무선 회선 제어 채널 | **NAS 시그널링 / IMS(SIP)** |
| SMS PDU(140바이트) | 그대로 | **그대로** |
| SMSC 보관후전달 | 그대로 | **그대로** |

운반 계층(트럭)만 회선 채널 → IP 시그널링으로 바뀌었을 뿐, **140바이트 PDU와 SMSC 구조(편지 알맹이)는 그대로**다. 그래서 백엔드에서 문자 중계사 API로 SMS를 쏘는 코드는 세대와 무관하게 동일하다. → [SMS-기술규격](SMS-기술규격.md)
