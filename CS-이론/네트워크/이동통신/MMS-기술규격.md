# MMS 기술 규격

> 최종 업데이트: 2026-06-13 | 3GPP TS 23.140 / OMA MMS 기준

## 개념

**MMS(Multimedia Message Service, 멀티미디어 메시지 서비스)** 는 **사진·동영상·오디오와 장문 텍스트를 주고받는 메시지 서비스**다. SMS가 짧은 텍스트만 다루는 한계를 넘기 위해, **패킷 데이터망(IP) 기반의 별도 메시징 시스템**으로 설계됐다.

> 비유: SMS가 **엽서**(짧은 글, 회선으로 바로 배달)라면, MMS는 **택배**다. 큰 짐(사진·동영상)을 택배사 창고(MMSC)에 맡기고, 받는 사람에겐 "택배 왔으니 찾아가세요" 알림만 보낸 뒤, 데이터망으로 내려받게 한다.

핵심은 MMS가 [SMS](SMS-기술규격.md)의 확장이 **아니라**, 회선 제어 채널이 아닌 **인터넷(데이터망) + 중앙 서버**를 쓰는 완전히 다른 메커니즘이라는 점이다. 그래서 140바이트 같은 SMS의 벽에서 자유롭다.

## 배경/역사

| 연도 | 사건 |
|------|------|
| 2002 | **3GPP TS 23.140**으로 MMS 표준화. WAP·SMTP 전송, SMIL·MIME 포맷 규정 |
| 2002~ | **OMA(Open Mobile Alliance)** 가 3GPP와 공동으로 MMS 프로토콜 정의·확장 |
| 2000년대 중반 | 카메라폰 보급과 함께 사진 전송 수단으로 대중화 |
| 2010년대 | OTT 메신저(카카오톡 등)에 멀티미디어 전송 영역 잠식 |
| 현재 | 개인 간 사용은 줄었으나 **B2C 광고·브랜드 메시지(이미지 첨부)** 로 잔존 |

MMS는 3GPP와 OMA **두 표준화 기구가 함께** 정의했다. 3GPP가 통신망 관점 규격(TS 23.140)을, OMA가 단말·응용 관점 규격을 맡아 상호 보완한다.

## SMS와 근본적으로 다른 점 — 서버 경유 + 데이터망

| 구분 | SMS | MMS |
|------|-----|-----|
| 운반 통로 | 회선 **제어 채널**(SDCCH) 또는 NAS/IMS | **패킷 데이터망(IP)** |
| 전달 방식 | PDU를 수신자에 **직접 푸시** | **MMSC 서버**에 올렸다 내려받음 |
| 용량 | 140바이트 (벽) | 수백 KB~수 MB (사업자별) |
| 본문 형식 | 텍스트(인코딩표) | **멀티미디어**(이미지·영상·텍스트) |

SMS는 메시지를 수신자에게 곧장 밀어 넣지만, MMS는 **서버에 보관해두고 알림만 짧게 주는** 방식이라 대용량이 가능하다.

## 전송 방식 — MMSC 서버 경유

MMS는 **"본문은 데이터망으로 서버에 올렸다 받고, 도착 알림만 SMS로 주는"** 구조다.

```
① 발신 단말 ─(데이터망/WAP·HTTP)→ [MMSC]에 본문 업로드
② MMSC ─(SMS 알림 = MMS Notification)→ 수신 단말: "메시지 도착했어"
③ 수신 단말 ─(데이터망)→ [MMSC]에서 본문 다운로드
```

- 본문(사진·영상)은 **데이터망(IP)** 으로 오가니 용량이 큼
- 수신자에게 가는 **도착 알림만 SMS** 를 빌려 씀 (짧으니 140바이트로 충분)
- 수신 단말이 데이터 연결로 MMSC에서 실제 콘텐츠를 가져와 표시

## 구성 요소

| 요소 | 역할 |
|------|------|
| **MMSC** (MMS Center) | MMS의 중앙 서버. 메시지 저장·전달·변환 담당 |
| **MM1** | 단말 ↔ MMSC 프로토콜 (WAP/HTTP 기반, 업로드·다운로드) |
| **MM4** | MMSC ↔ 다른 사업자 MMSC 간 연동 (SMTP/ESMTP 기반) |
| **MM7** | 부가서비스(VAS) ↔ MMSC. **기업 대량 발송**이 타는 경로 |

### 메시지 포맷 — SMIL + MIME

MMS 본문은 여러 미디어를 한 메시지에 담아야 하므로 두 포맷을 쓴다.

- **MIME**: 이미지·텍스트·오디오 등 여러 파트를 **멀티파트로 묶는** 형식 (이메일 첨부와 동일 개념)
- **SMIL**: 이 미디어들을 **언제·어디에 배치할지** 정의하는 레이아웃·타이밍 언어 (슬라이드쇼처럼)

## 용량 — 사업자별로 다르다

MMS 용량은 3GPP 표준이 못박은 값이 **아니라 사업자·단말이 정하는 운영 기준**이다.

- 한국 통신사 MMS: 보통 **텍스트 2,000바이트 + 이미지 첨부(수백 KB~약 1 MB)** 수준
- 정확한 첨부 한도는 통신사·중계사마다 다르므로, 발송 전 해당 API 스펙을 확인해야 한다

> 첨부 용량을 단정하지 않는 이유: SMS의 90바이트처럼 MMS 첨부 한도도 사업자 정책이라, "표준상 N MB"라고 못박을 수 없다.

## 백엔드에서 MMS 발송

서버에서 MMS도 직접 망에 쏘지 않고 **문자 중계사 API**를 거친다. 이미지 첨부는 보통 파일을 함께 업로드하는 형태다.

```
백엔드 서버 → 문자 중계사 API(HTTP, 이미지 첨부) → MMSC → 데이터망 → 수신 단말
```

- 국내: NHN Cloud, 알리고, 네이버 클라우드 SENS 등 (SMS/LMS/MMS 통합 API 제공)
- 텍스트만 길게 보내면 **LMS**, 이미지가 붙으면 **MMS**로 과금 등급이 갈린다 → [LMS-기술규격](LMS-기술규격.md)

## 정리

- **MMS** = 멀티미디어(사진·영상·장문) 메시지. 표준은 3GPP TS 23.140 + OMA
- SMS와 달리 **패킷 데이터망 + MMSC 서버 경유** → 대용량 가능
- 전송: **본문은 데이터망으로 서버에 올렸다 받고, 알림만 SMS**
- 포맷: **MIME(멀티파트) + SMIL(레이아웃)**
- 용량은 **사업자별 운영 기준** (표준 고정값 아님)
