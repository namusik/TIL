# Linked List 연결 리스트

> 최종 업데이트: 2026-09-08 | CS 이론 보편 개념 기준 (특정 언어 비종속)

## 개념

**데이터를 담은 노드(node)들이, 각자 "다음 노드의 위치(포인터)"를 들고 서로를 가리키며 이어진 자료구조.** [배열](../Array/Array.md)과 정반대로, 원소들이 메모리에 **연속으로 붙어 있지 않고 힙 여기저기 흩어져** 있으며, 그 흩어진 조각들을 포인터가 실처럼 이어준다.

> 보물찾기 쪽지와 같다. 배열은 아파트 우편함처럼 칸이 나란히 붙어 있어 "102호"라고 하면 바로 찾아가지만, 연결 리스트는 **"다음 쪽지는 나무 밑에 있다"**는 메모만 들고 있는 쪽지들의 연쇄다. 다섯 번째 쪽지를 찾으려면 첫 쪽지부터 순서대로 따라가야지, 다섯 번째로 곧장 점프할 방법이 없다.

## 배경/역사

연결 리스트의 개념은 **Hans Peter Luhn**이 1953년 1월 IBM 내부 메모에서 **체이닝 해시 테이블**을 위한 아이디어로 처음 제안한 것으로 거슬러 올라간다. 실제 컴퓨터과학 구현으로는 **Allen Newell, Cliff Shaw, Herbert A. Simon**이 1955~56년 RAND Corporation과 CMU에서 **IPL(Information Processing Language)**의 핵심 자료구조로 만든 것이 최초로 꼽힌다. 이후 **John McCarthy**가 1958년 **Lisp**를 설계하며 `car`(데이터)/`cdr`(다음 노드 참조)로 구성된 **cons cell**을 연결 리스트로 그대로 활용했고, 이것이 함수형 언어에서 연결 리스트가 근본 자료구조로 자리잡는 데 가장 큰 영향을 미쳤다.

## 노드 구조

연결 리스트를 이루는 최소 단위는 **노드(node)** 다. 노드는 항상 두 부분으로 구성된다.

| 구성 | 의미 |
|------|------|
| **데이터(data)** | 실제 저장하려는 값 |
| **포인터(pointer/reference)** | 다음(그리고 종류에 따라 이전) 노드의 메모리 위치 |

```text
[데이터 | next] → [데이터 | next] → [데이터 | next] → null
```

배열이 "인덱스 → 주소 계산"으로 원소를 찾는 것과 달리, 연결 리스트는 **각 노드가 다음 위치를 직접 들고 있어야만** 리스트가 이어진다 — 포인터 자체가 구조를 이루는 재료다.

## 종류

| 종류 | 구조 | 특징 |
|------|------|------|
| **단일 연결 리스트** (Singly) | `next`만 있음 | 한 방향으로만 순회 가능 |
| **이중 연결 리스트** (Doubly) | `next` + `prev` | 양방향 순회, 노드 하나만 알아도 삭제 가능 |
| **원형 연결 리스트** (Circular) | 마지막 노드가 `null` 대신 **첫 노드를 다시 가리킴** | 스케줄링처럼 "돌고 도는" 데이터에 적합 |

## 연산별 시간 복잡도

| 연산 | 시간 복잡도 | 이유 |
|------|------------|------|
| 인덱스/위치 접근 (`get(i)`) | **O(n)** | 주소 계산이 불가능해 처음부터 포인터를 따라가야 함 |
| 값 검색 | O(n) | 배열과 동일 — 순회 필요 |
| **맨 앞** 추가/삭제 | **O(1)** | 머리 포인터만 갱신 |
| **맨 뒤** 추가/삭제 | O(1)\* | 꼬리 포인터를 별도로 관리할 때만. 없으면 O(n) |
| **중간** 추가/삭제 (노드를 이미 알 때) | **O(1)** | 앞뒤 포인터만 재연결 |
| **중간** 추가/삭제 (인덱스로 지정) | O(n) | **그 노드까지 찾아가는 순회 비용**이 실제로는 지배적 |

**핵심 포인트** — "연결 리스트는 중간 삽입/삭제가 O(1)"이라는 말은 **이미 그 노드를 가리키는 포인터(또는 이터레이터)를 들고 있을 때만** 참이다. 인덱스로 위치를 지정하면 그 자리를 찾아가는 데만 O(n)이 걸려, 배열의 O(n)(원소 밀기)과 총량은 별 차이가 없다.

## 왜 인덱스 접근이 O(n)인가 — 배열과의 근본적 차이

[배열](../Array/Array.md#메모리-구조와-임의-접근-random-access)은 `주소 = 시작 주소 + (인덱스 × 원소 크기)`라는 **산술 계산 한 번**으로 아무 위치나 O(1)에 접근한다. 연결 리스트는 노드가 메모리 어디에 있을지 예측할 수 없으므로 이 계산이 통하지 않는다 — **머리(head)부터 포인터를 하나씩 따라가는 것만이 유일한 방법**이다. 그래서 "임의 접근(random access)"이 불가능하고 "순차 접근(sequential access)"만 가능하다.

## 캐시 지역성 문제 — 이론과 실측의 간극

노드가 힙 여기저기 흩어져 있다는 점은 Big-O로 드러나지 않는 비용을 만든다. CPU는 메모리를 읽을 때 캐시 라인 단위로 **주변 데이터를 한꺼번에** 가져오는데, 연결 리스트는 다음 노드가 어디 있을지 예측 불가능해 **매 노드 접근마다 캐시 미스**가 나기 쉽다. 배열은 원소들이 붙어 있어 이 혜택을 그대로 받는다. 그 결과 이론상 같은 O(n) 순회여도 **실측 성능은 배열이 훨씬 빠른 경우가 흔하다** — 이론적 시간복잡도만으로 자료구조를 고르면 안 되는 대표적 사례다.

## 배열과의 비교, 언어별 이름

전반적인 트레이드오프(메모리 배치·캐시 효율 포함 비교표)는 [Array — 배열 vs 연결 리스트](../Array/Array.md#배열-vs-연결-리스트)에서 다룬다. 이 개념 자체는 특정 언어에 종속되지 않으며, 각 언어가 다른 이름으로 표준 라이브러리에 포함하고 있다.

| 언어 | 이름 |
|------|------|
| Java | `LinkedList` (이중 연결) |
| C++ | `std::list` (이중 연결), `std::forward_list` (단일 연결) |
| C# | `LinkedList<T>` (이중 연결) |
| Python | 내장 타입 없음 — `collections.deque`가 유사한 역할 |
| Rust | `std::collections::LinkedList` (이중 연결) |

Java에서의 구체적 사용법·`ArrayList`와의 실전 비교는 → [Java-List](../../../Java/Java-Collection.md/Java-List.md#linkedlist)에서 다룬다.
