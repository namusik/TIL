# 선언형 vs 명령형 (Declarative vs Imperative)

> 최종 업데이트: 2026-07-31 | 프로그래밍·인프라 패러다임

## 개념

프로그램이나 시스템에게 일을 시키는 두 가지 방식이다.

- **명령형(Imperative)** — **"어떻게(How)"** 를 단계별로 지시한다
- **선언형(Declarative)** — **"무엇(What)"**, 즉 원하는 최종 상태만 기술하고 과정은 시스템에 맡긴다

> 내비게이션과 같다. **명령형**은 "여기서 좌회전, 다음 신호서 우회전…"을 계속 불러주는 것이고, **선언형**은 **"목적지: 강남역"** 만 찍는 것이다. 경로 탐색과 재조정은 내비가 알아서 한다.

## 대비

| | 명령형 (How) | 선언형 (What) |
|---|-------------|---------------|
| 말하는 것 | 과정·순서 | **최종 목표 상태** |
| 현재 상태 파악 | **사람/코드가** 직접 | **시스템이** 알아서 비교 |
| 반복 실행 | 문제 생김(중복·에러) | **멱등** — 몇 번 해도 같은 결과 |
| 제어 | 세밀함 | 추상화에 맡김 |

## 코드로 보기

같은 작업(짝수만 골라 2배)을 두 방식으로.

```java
// 명령형 — 어떻게: 루프 돌며 하나씩 처리
List<Integer> result = new ArrayList<>();
for (int n : nums) {
    if (n % 2 == 0) result.add(n * 2);
}

// 선언형 — 무엇을: "짝수를 2배로"만 기술
nums.stream().filter(n -> n % 2 == 0).map(n -> n * 2).toList();
```

선언형은 "루프를 어떻게 도는지"를 감추고 **의도만** 드러낸다.

## 어디서 나타나나

같은 패러다임이 여러 층위에서 반복된다.

| 영역 | 명령형 | 선언형 |
|------|--------|--------|
| **언어** | `for` 루프로 직접 순회 | **SQL**, Stream(`map`·`filter`), 함수형 |
| **UI** | DOM 직접 조작(jQuery) | **React** JSX ("이 상태면 이 화면") |
| **인프라** | `kubectl` 명령·셸 스크립트 | **K8s YAML**, Terraform, [Argo](../DevOps/Argo/Argo-개념.md) |
| **빌드** | 셸 스크립트로 단계 나열 | Dockerfile |

**SQL**이 대표적이다 — `SELECT ... WHERE`로 **무엇을 원하는지**만 쓰고, **어떻게 찾을지**(인덱스 스캔·조인 순서)는 옵티마이저가 정한다. (→ [database-index](../Database/데이터베이스-이론/database-index.md))

```
# 명령형
kubectl scale deployment app --replicas=3

# 선언형 (deployment.yaml) — "3개가 떠 있어야 한다"만 선언
spec:
  replicas: 3
```

## 선언형의 강점

| 이점 | 내용 |
|------|------|
| **멱등성** | 여러 번 적용해도 안전(이미 목표면 안 건드림). 명령형은 반복하면 중복·에러 |
| **재현성** | 선언 파일이 "진실" → 언제든 같은 상태 재현 |
| **자동 수렴** | 현재가 목표와 다르면 시스템이 **스스로 맞춘다**(reconciliation) |
| **의도가 드러남** | 코드가 "무엇을 원하는지"를 보여줘 읽기 쉬움 |

## 선언형의 한계

만능은 아니다.

- **세밀한 제어가 어렵다** — "어떻게"를 시스템이 정하므로, 특정 순서·최적화를 강제하기 힘들다.
- **블랙박스성** — 원하는 대로 안 될 때 **"왜 이렇게 됐지"** 파악이 어렵다(추상화 뒤가 안 보임).
- **성능 튜닝 시 내부 이해 필요** — SQL이 느릴 때 결국 옵티마이저·실행계획을 이해해야 하듯, 선언형도 내부 동작을 알아야 할 때가 온다.

## 인프라에서 — reconciliation loop

선언형이 인프라에서 특히 빛나는 이유다. **원하는 상태를 선언**해두면, 컨트롤러가 **현재 상태와 끊임없이 비교해 목표로 수렴**시킨다.

```
원하는 상태(Git YAML)  ──▶  컨트롤러가 현재와 비교(diff)  ──▶  다르면 맞춤(sync)
        ▲                                                          │
        └──────────────── 계속 반복(reconciliation loop) ◀─────────┘
```

이 덕분에 **자동 복구(self-heal)**가 된다 — 누가 수동으로 바꿔도 선언한 상태로 되돌린다. K8s·[Argo](../DevOps/Argo/Argo-개념.md)가 이 원리로 동작한다.

## 한 줄 정리

> **명령형은 "어떻게"를 단계별로 지시하고, 선언형은 "무엇(원하는 최종 상태)"만 기술해 시스템이 알아서 맞추게 한다. 내비에 목적지만 찍는 것과 같다. SQL·함수형·React·K8s·Terraform이 모두 선언형이며, 멱등성·재현성·자동 수렴이 강점이지만 세밀한 제어와 디버깅은 어렵다는 한계가 있다.**
