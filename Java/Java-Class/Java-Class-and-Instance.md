# 클래스와 인스턴스 (Class & Instance)

> 최종 업데이트: 2026-07-16 | Java 기준

## 개념

- **클래스(Class)** = 객체를 만들기 위한 **설계도**
- **인스턴스(Instance)** = 그 설계도로 찍어낸 **실제 객체**

클래스는 "어떤 데이터(필드)와 동작(메서드)을 가질지"를 정의만 할 뿐, 그 자체로는 메모리에 실체가 없다. `new`로 인스턴스를 만들어야 비로소 실제 데이터를 담는 객체가 생긴다.

> 붕어빵 틀(클래스)과 붕어빵(인스턴스)의 관계다. 틀은 모양만 정의하고, 실제로 먹을 수 있는 붕어빵은 틀로 찍어낸 것이다. 틀 하나로 붕어빵을 여러 개 만들 수 있고, 각 붕어빵은 **따로 존재**한다(하나는 팥, 하나는 슈크림).

## 클래스 — 설계도

필드(상태)와 메서드(동작)를 정의한다.

```java
public class Dog {
    String name;              // 필드 — 각 인스턴스가 가질 상태
    void bark() {             // 메서드 — 동작
        System.out.println(name + ": 멍멍");
    }
}
```

이 시점엔 아직 **개 한 마리도 없다.** 설계도만 있다.

## 인스턴스 — new로 만든 실제 객체

`new`로 설계도를 실체화한다. 이때 객체는 **힙(heap) 메모리**에 생성된다.

```java
Dog d1 = new Dog();   // 인스턴스 ① 생성
Dog d2 = new Dog();   // 인스턴스 ② 생성 (①과 완전히 별개)

d1.name = "바둑이";
d2.name = "흰둥이";
```

`new Dog()`를 두 번 했으니 **서로 독립된 개 객체가 2개** 만들어졌다.

## 인스턴스는 각자 독립된 상태를 가진다

같은 클래스로 만들어도, 인스턴스마다 **필드값을 따로** 가진다.

```java
d1.bark();   // 바둑이: 멍멍
d2.bark();   // 흰둥이: 멍멍
```

`d1`의 `name`을 바꿔도 `d2`는 영향받지 않는다. 붕어빵 하나에 팥을 넣어도 옆 붕어빵은 그대로인 것과 같다.

## 객체(object) vs 인스턴스(instance) — 용어

거의 같은 말로 쓰이지만 뉘앙스가 조금 다르다.

| 용어 | 강조점 |
|------|--------|
| **객체(object)** | 실체가 있는 것 자체 |
| **인스턴스(instance)** | **"특정 클래스의"** 객체임을 강조 ("Dog의 인스턴스") |

실무에서는 혼용해도 무방하다. "Dog 객체 = Dog의 인스턴스"다.

## 참조 변수 — 인스턴스를 가리키는 리모컨

`Dog d1 = new Dog();`에서 `d1`은 **객체 자체가 아니라, 힙에 있는 객체를 가리키는 참조(주소)**다. 변수는 스택에, 실제 객체는 힙에 있다.

| 위치 | 담는 것 |
|------|---------|
| **스택(stack)** | 참조 변수 `d1`, `d2` (객체의 주소) |
| **힙(heap)** | 실제 `Dog` 객체 |

> 변수는 TV(객체)가 아니라 **리모컨**이다. 리모컨(참조)을 복사해 넘겨도 TV는 하나다.

그래서 참조를 복사하면 **같은 객체를 가리킨다** — 흔한 실수 지점이다.

```java
Dog a = new Dog();
Dog b = a;            // 객체 복사 X — 같은 객체를 가리키는 참조만 복사
b.name = "루시";
System.out.println(a.name);   // "루시" — a와 b가 같은 객체이기 때문
```

메모리 구조 상세는 → [Java Memory](../Java-Theory/Java-Memory.md), 안 쓰는 객체 회수는 → [Garbage Collection](../Java-Theory/Java-Garbage-Collection.md).

## static — 인스턴스가 아니라 클래스에 속한다

`static`이 붙은 필드·메서드는 **인스턴스가 아니라 클래스 자체에 소속**된다. 그래서 인스턴스를 만들지 않고도 쓰며, 모든 인스턴스가 **하나를 공유**한다.

```java
public class Dog {
    static int count = 0;   // 클래스 소속 — 전체가 공유
    String name;            // 인스턴스 소속 — 각자 따로

    Dog() { count++; }      // 개가 생길 때마다 공유 카운터 증가
}

new Dog(); new Dog();
System.out.println(Dog.count);   // 2 — 인스턴스 없이 클래스명으로 접근
```

| | 인스턴스 멤버 | static 멤버 |
|---|--------------|-------------|
| 소속 | 각 인스턴스 | 클래스 |
| 접근 | `d1.name` | `Dog.count` |
| 공유 | 인스턴스마다 따로 | 전체가 하나 공유 |

## 생성자 (Constructor)

`new`로 인스턴스를 만들 때 **자동 호출되어 초기 상태를 세팅**하는 특수 메서드다. 클래스명과 같고 반환형이 없다.

```java
public class Dog {
    String name;
    Dog(String name) {        // 생성자
        this.name = name;     // this = 지금 만들어지는 그 인스턴스
    }
}

Dog d = new Dog("바둑이");   // 생성자가 name을 "바둑이"로 초기화
```

여기서 `this`는 **지금 생성 중인 바로 그 인스턴스**를 가리킨다.

## 정리

- **클래스 = 설계도, 인스턴스 = `new`로 만든 실제 객체**
- 인스턴스는 **힙**에 생기고, 인스턴스마다 **독립된 필드값**을 가진다
- 참조 변수는 객체가 아니라 **객체를 가리키는 주소** — 복사하면 같은 객체를 가리킨다
- **static**은 인스턴스가 아니라 **클래스에 소속**되어 전체가 공유한다
- **생성자**는 `new` 시 호출되어 인스턴스를 초기화한다
